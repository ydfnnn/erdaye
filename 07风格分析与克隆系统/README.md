# 07风格分析与克隆系统

> SC-IMG 规范 1.0.0 · 信息图形知识库的风格提取、迁移与验收模块

从参考图提取带证据的风格档案，把其中的视觉关系迁移到新主题。系统以同一份生成规范导出**中文 JSON、英文 JSON、中文简易提示词、详细自然语言提示词**。信息图形项目由 01–05 和 06 的记录提供数据、关系、叙事和编码依据。 [仓库总入口](../README.md)

## 启动

将下列启动语与参考图、已有档案或本次任务交给能访问 GitHub 的模型。

> 启动风格分析和克隆系统。请读取 ydfnnn/erdaye 仓库中 07风格分析与克隆系统的 SYSTEM.md 和 manifest.json，报告实际读取的版本。若本轮有参考图，请建立风格档案。若已给指定风格档案和新主题，请按仓库联动规则适配，并输出四版提示词。

- **直接读取。** 使用 [SYSTEM.md 原文](https://raw.githubusercontent.com/ydfnnn/erdaye/main/07%E9%A3%8E%E6%A0%BC%E5%88%86%E6%9E%90%E4%B8%8E%E5%85%8B%E9%9A%86%E7%B3%BB%E7%BB%9F/SYSTEM.md) 与 [manifest.json](https://raw.githubusercontent.com/ydfnnn/erdaye/main/07%E9%A3%8E%E6%A0%BC%E5%88%86%E6%9E%90%E4%B8%8E%E5%85%8B%E9%9A%86%E7%B3%BB%E7%BB%9F/manifest.json)。需要固定版本时用同一提交中的两份文件。
- **上传文档。** 下载运行正文后上传，与参考图或档案一起使用。「启动」后，模型应报告已读取的系统、档案与当前任务。
- **记忆调用。** 使用已写入仓库地址的[记忆调用卡](./MEMORY.md)，登记实际档案 ID、版本及可读位置。只有摘要时，报告摘要的证据范围。

## 用在仓库哪个环节

| 上游输入 | 07 的处理 | 下游交付 |
|---|---|---|
| 02 的案例原图或来源、观察和字典 | 分开标注风格、内容和版式参考，提取十三项观察与可迁移规则 | 有区域证据的版本化风格档案 |
| 06 的基础数据、叙事方案与视觉编码 | 把需要保持的字段、序列、单位、图例和文字列为项目锁定，并明确可换的表现 | 按任务适配的生成规范及四版提示词 |
| 06 实施阶段的实际图像与设计记录 | 对照事实、编码、风格与可读性，记录通过、偏差或未知 | 验收记录和新的图像或任务版本。完成案例核验后可更新 02 的方法关联 |

主归属沿用 01 的五种组织逻辑。03 图符、04 统计和 05 知觉组织为各自适用的任务提供编码依据。根目录的 07 是仓库级方法模块。06 项目内的阶段 07 用于信息轮盘测试。 [完整联动说明](./00-仓库联动说明.md)

## 运行示例校验

在本模块目录使用 Node.js 18 或更高版本。模型直接读文档时可独立按运行正文工作。

    node tools/verify.cjs
    node tools/export-prompts.cjs examples/case-0002.render.json examples/style-profile.json examples/case-0002.task.json

导出器核对档案版本、核心覆盖、依赖、项目锁定、画幅和准确文案。译文含义与最终图像由审查者依据条款和实际成品核验。
